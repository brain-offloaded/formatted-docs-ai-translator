현재 formatted-docs-ai-translator 앱에는 텍스트 번역만 있어. 이제는 이미지 번역을 새로 만들 거야. 기존 구조를 최대한 유지하는 것이 목표해야 해. 단, 이미지의 특성상 프롬프트 등의 부분에는 의도적인 변화가 있을 거야. 특히, 파싱(parseChannel)을 수행하지 않고, 번역(translateChannel) 과정에서 파싱과 번역이 동시에 수행될 거야. 물론 조립(applyChannel)는 정상적으로 수행할 거야.
따라서 @/docs 를 참고하며 작업하되, 이미지에 특화된 내용은 새로운 문서로 남겨줘.
또, ocr을 위해서, @/src/ai/schema.ts 의 imageOcrTranslationJsonSchema를 사용하게 해줘.

- parse channel: 아무 것도 하지 않음
- translate channel: openai 라이브러리를 사용, 위의 response schema와 함께 프롬프트를 통해서 응답을 받음
  - 이미지 전용 프롬프트도 프롬프트 프리셋에서 관리
  - 다만 번역 타입에 따른 구분 필드가 추가
    - type이 text, image라는 enum을 사용
    - 번역할 때는 타입에 맞는 프롬프트만 선택 가능
  - ai에게 요청을 날릴 때에는 response_format를 사용해서 json_format을 입력, 프롬프트에는 json 스키마 내용이 들어가지 않음
  - ocr은 전적으로 llm api에 의존. 한 번의 요청으로 ocr과 번역을 동시에 처리함.
- apply channel: 앞(translate channel)의 응답을 활용, 이미지를 재조립하여 결과물을 내보냄


- 텍스트 번역과는 다르기에 탭을 분리하나, 기본적인 기능은 동일함.
  - 이미지 번역 탭은 선택하면 예제 프리셋 선택 불가
  - 이미지 번역 탭은 프롬프트 프리셋 중 이미지만 선택 가능
    - 텍스트 번역 탭은 반대로 프롬프트 프리셋 중 텍스트만 선택 가능
  - 이미지 번역 탭은 텍스트 번역 탭과 동일하게 파일을 입력받으며, 여러 개의 파일을 입력받을 경우 순차처리한 다음 zip으로 리턴함
- 프롬프트 프리셋과 프롬프트 converter는 최대한 동일하게 사용하도록 함
  - 필요 시, 모듈화 할 수 있는 기능들은 따로 모듈화하여 텍스트 번역과 공유해서 사용하도록 변경
  - ImageTranslatorService는 프론트엔드에서 선택한 프롬프트 프리셋을 사용하며, ai 세팅도 프론트엔드에서 선택한대로 사용
- 전반적인 ui 등의 경험은 최대한 유지되도록 함
- 번역 캐싱은 `${파일명}:${해시}` 형태로 진행
